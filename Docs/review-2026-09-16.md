# Repository checkpoint review — 2026-09-16

Reviewed first-party shared C++ gameplay/compatibility/data parsing, Windows native
bridge, Unity authoring and presentation, Simulant input/rendering/audio hosts,
asset conversion and disc staging/build scripts, regression checks and project
documentation. Unity/package caches, downloaded engine/SDK sources and the Flycast
installation are external dependencies, not part of this source review.

## Architecture

`Game/` remains free of Unity, Simulant, SDL, KOS and Windows dependencies. Shared
C++ owns movement, collision resolution, key/door state, camera transitions and
sound events. Host code handles device mappings, native ABI, rendering and playback.
Unity exports portable room text, audio manifests/PCM WAVs and bounded vertex/RGB565
data. Lighting is baked into vertex colors; Unity lights are not a runtime dependency.
No new gameplay framework or engine-wide compatibility API was introduced.

Audio remains capped at eight clips, two placed sounds, eight voices and 512 KiB
PCM. Static visuals share 4,096 triangles, 32 parts, eight textures and 512 KiB
RGB565 pixels. The saved sample currently exports 2,772 static triangles, 21 parts,
256 KiB textures and 258,736 PCM bytes. These are subsystem budgets, not a full
real-hardware memory certification.

## Remaining scope

Real Dreamcast execution, peak RAM/VRAM and hardware performance remain untested.
Lighting has no cast shadows, occlusion, bounce or moving-object illumination;
vertex subdivision has a fixed budget. Audio is resident mono PCM with distance
gain, not streaming, positional stereo or reverb. The collision solver is flat
X/Z with boxes and circular footprints; it is not general 3D physics. Dynamic
model bindings, skeletal animation and animation-synchronized footsteps remain
future work. The previously reported intermittent WASD loss has not been reproduced
by the synthetic input checks and is not claimed fixed.

The existing WSL toolchain installation is documented in `Simulant/README.md`;
this is not an automated fresh-machine installer. Source/license details for
the user-supplied AC FBX and downloaded hum have not been provided. Blender remains
the canonical workflow for future model edits; no `.blend` source was supplied.
